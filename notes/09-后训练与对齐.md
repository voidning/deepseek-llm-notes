## 9.1 为什么后训练与对齐决定模型「能不能用」

> **我：** 后训练与对齐这也是非常关键的一步吧，能详细讲解一下吗

是的，**后训练与对齐非常关键，甚至可以说决定了一个大模型"能不能用、好不好用、安不安全"**。

预训练让模型学会了语言规律和世界知识，但它本质上还是一个"超级续写器"：你给它一句话，它会接着往下编。它不一定会听指令，也不一定安全、诚实、有用。后训练与对齐，就是把这个"会续写的模型"变成"会帮忙、守规矩、符合人类偏好的助手"。

可以打个比方：

- **预训练**：读了海量书，知识很多，但像个野生天才。
- **SFT**：教它基本礼仪和答题格式。
- **奖励模型 / RLHF**：请老师根据人类偏好不断调教它。
- **安全对齐**：给它交通规则和法律底线。
- **部署后监控**：上路后继续观察、纠正。

### 后训练和预训练有什么区别

| 维度 | 预训练 | 后训练 |
|---|---|---|
| 数据 | 海量互联网文本 | 高质量指令、对话、偏好数据 |
| 目标 | 预测下一个 token | 遵循指令、符合偏好、安全 |
| 数据量 | 万亿 token 级 | 百万到十亿 token 级 |
| 损失 | 交叉熵 | 交叉熵、偏好损失、RL 目标 |
| 成本 | 极高 | 相对低，但很关键 |
| 结果 | 基础模型 Base Model | 指令模型 / 对话模型 / 对齐模型 |

预训练完的模型叫 **Base Model**。
它可能知道很多，但你问它"帮我写个邮件"，它可能继续续写"帮我写个邮件"这句话，而不是真的写邮件。后训练之后，才变成 ChatGPT、Claude、Gemini 那种助手。

## 9.2 第一阶段：监督微调 SFT

**SFT = Supervised Fine-Tuning，监督微调。**

### 数据长什么样

主要是"指令-回答"对：

```text
用户：帮我用 Python 写一个快速排序。
助手：好的，下面是一个示例……
```

多轮对话：

```text
用户：北京天气怎么样？
助手：我没法实时查天气，但可以告诉你……
用户：那帮我写个查询天气的代码。
助手：可以，下面是一个调用 API 的示例……
```

也可能包括：思维链数据、工具调用数据、代码/数学/推理数据、安全拒绝数据、角色扮演数据、多语言数据。

### 训练损失

还是交叉熵，但通常**只对助手回复部分算损失**。用户输入部分被 mask 掉，不参与损失。

$$L_{\text{SFT}} = -\sum_{t \in \text{assistant tokens}} \log \pi_\theta(y_t \mid x, y_{<t})$$

意思是：模型看到用户问题和前文，要预测助手的下一个 token。

### SFT 的作用

- 学会指令格式
- 学会多轮对话
- 学会拒绝危险请求
- 学会工具调用格式
- 激活预训练里学到的知识

但 SFT 有个问题：它只告诉模型"标准答案是什么"，没告诉它"两个回答哪个更好"。所以需要偏好优化。

---

## 9.3 第二阶段：奖励模型 RM

**RM = Reward Model，奖励模型。**

人类更擅长比较，不擅长打绝对分数。所以通常让人类看同一个 prompt 的两个回答，选哪个更好。

```text
prompt: 解释一下相对论。
回答 A：……（更好）
回答 B：……（更差）
人类选择：A
```

然后训练一个奖励模型，给回答打分 $r_\phi(x, y)$，目标：好回答分数高，差回答分数低。

常用 Bradley-Terry 模型：

$$P(y_w \succ y_l \mid x) = \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))$$

损失：

$$L_{\text{RM}} = -\log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))$$

其中 $y_w$ 是 winning（更好的回答），$y_l$ 是 losing（更差的回答），$\sigma$ 是 sigmoid。

奖励模型可以理解成一个"人类偏好模拟器"。它比人类便宜、快、可批量调用。

但 RM 也会被"钻空子"，叫 **reward hacking**。模型可能学会输出让 RM 打高分、但人类觉得垃圾的内容。所以要多个 RM、KL 惩罚、定期人工评估。

---

## 9.4 第三阶段：RLHF / PPO

**RLHF = Reinforcement Learning from Human Feedback，基于人类反馈的强化学习。**

最经典流程：

1. 预训练模型 → Base Model
2. SFT → SFT Model
3. 人类偏好数据 → 训练 Reward Model
4. 用 RM 作为奖励，用 PPO 优化策略模型

策略模型就是我们要训练的模型。参考模型通常是 SFT 模型，冻结不动。

目标函数：

$$\max_\pi \mathbb{E}_{x \sim D, y \sim \pi(\cdot|x)}\left[r_\phi(x, y) - \beta D_{\text{KL}}(\pi(\cdot|x) \| \pi_{\text{ref}}(\cdot|x))\right]$$

解释：

- $r_\phi(x, y)$：奖励模型给的分，越高越好。
- $D_{\text{KL}}$：KL 散度，惩罚新模型偏离参考模型太远。
- $\beta$：控制惩罚强度。

**为什么加 KL 惩罚？** 因为如果只最大化奖励，模型会疯狂钻 RM 漏洞，输出乱码或谄媚内容。KL 惩罚让它别跑太偏，保持语言能力和多样性。

PPO 是强化学习算法，负责更新策略。它需要：策略模型、参考模型、奖励模型、价值模型 Critic、优势估计、裁剪目标。

RLHF 效果很好，但非常复杂、不稳定、贵。训练时容易崩，loss spike，reward 上升但人类觉得变差。

---

## 9.5 第四阶段：DPO 等直接偏好优化

因为 RLHF 太麻烦，后来出现了 **DPO = Direct Preference Optimization**。

DPO 的核心思想：

> 不显式训练奖励模型，也不跑 PPO，直接用偏好对优化策略。

数据还是 `prompt, 好回答 y_w, 差回答 y_l`。DPO 损失大致是：

$$L_{\text{DPO}} = -\log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right)$$

直觉：

- 提高好回答的概率；
- 降低差回答的概率；
- 但不要偏离参考模型太远。

**优点**：不需要显式 RM；不需要 PPO；更稳定、更简单、更便宜；很多开源模型都用 DPO。

**缺点**：没有 RL 那种探索能力；对偏好数据质量敏感；可能不如精心调过的 RLHF。

**其他变体**：

- **IPO**：改进 DPO 的过拟合问题
- **KTO**：不需要成对偏好，只要"好/坏"标签
- **ORPO**：把 SFT 和偏好优化合在一起
- **SimPO**：更简单的偏好目标

## 9.6 RLAIF 与 Constitutional AI

**RLAIF = RL from AI Feedback，用 AI 反馈替代人类反馈。**

流程：

1. 让模型对同一个 prompt 生成多个回答。
2. 用另一个强模型或同一模型按规则打分、排序。
3. 用这些 AI 偏好数据训练 RM 或做 DPO。
4. 再优化策略模型。

**Constitutional AI，宪法 AI**：

- 给模型一套"宪法原则"，比如"不要伤害人类""不要歧视""要诚实"。
- 让模型自己批评自己的回答。
- 根据原则修订回答。
- 生成偏好数据。
- 再用 RLHF/DPO 训练。

**好处**：减少人类标注成本；可扩展；原则可调整。

**风险**：AI 反馈有偏见；原则设计很关键；可能形成"模型自己教自己"的闭环偏差。

## 9.7 对齐到底对齐什么

1. **有用 Helpful**：能回答问题；能写代码、翻译、总结、推理；能调用工具。
2. **诚实 Honest**：不胡编；不确定就说不知道；不伪造来源。
3. **无害 Harmless**：不提供危险信息；不歧视、不仇恨；不帮助违法。
4. **指令遵循 Instruction Following**：按格式输出；遵守长度、语气、角色要求。
5. **安全边界 Safety**：拒绝有害请求；不被越狱；不泄露隐私和系统提示。
6. **价值观与规范**：不同地区、文化、公司有不同规范；需要人工制定政策。

对齐不是"让模型变善良"这么简单，而是让它按设计者的目标、用户需求、安全规范行动。

---

## 9.8 安全对齐与红队

后训练之后还要做安全对齐：

- **红队测试**：专门找漏洞，比如越狱、诱导、注入。
- **对抗训练**：把攻击样本加入训练。
- **拒绝边界**：什么该拒绝，什么该回答。
- **系统提示**：定义角色、权限、安全规则。
- **输入输出过滤**：部署时加一层防护。
- **权限控制**：工具调用、代码执行、文件访问要受限。

重要：

> 安全不能只靠后训练。后训练只是其中一层，还需要系统级防护、监控、审计、限权。

---

## 9.9 后训练评估

怎么知道对齐变好了？

**自动评估**：MT-Bench、AlpacaEval、Arena Elo、MMLU、GSM8K、HumanEval、安全基准（如 ToxiGen、RealToxicityPrompts）。

**人工评估**：人类偏好胜率；有用性、诚实性、无害性打分；多轮对话质量；拒绝是否恰当。

**在线评估**：A/B 测试；用户反馈；举报率；留存、满意度。

要注意：自动评估可能被刷榜；人工评估贵且有偏见；安全评估要持续更新攻击样本。

---

## 9.10 常见问题与坑

1. **对齐税**：后训练后，模型在某些基础能力上可能下降。比如数学、代码、多语言能力。
2. **过度拒绝**：太安全，正常问题也拒绝。用户觉得不好用。
3. **谄媚**：模型迎合用户，哪怕用户是错的。为了拿高分，不敢反驳。
4. **奖励黑客**：模型钻 RM 漏洞。RM 分数高，但人类觉得差。
5. **灾难性遗忘**：后训练数据太窄，预训练能力丢失。
6. **偏好数据偏差**：标注者偏好不等于全人类偏好。文化、语言、价值观偏差。
7. **评估污染**：测试集泄漏进训练数据。分数虚高。

## 9.11 完整后训练流程

```text
预训练 Base Model
      ↓
SFT 监督微调
      ↓
收集偏好数据：人类 / AI / 规则
      ↓
训练 Reward Model 或直接用 DPO
      ↓
RLHF / PPO 或 DPO / IPO / KTO
      ↓
安全对齐、红队、对抗训练
      ↓
评估：自动 + 人工 + 在线
      ↓
部署
      ↓
持续监控、收集反馈、迭代
```

一句话：

> 预训练决定模型"知道什么"，后训练与对齐决定模型"怎么用这些知识、听谁的话、守什么规矩"。

后训练不是一次性步骤，而是一个持续迭代的过程。模型上线后，用户反馈、红队攻击、新政策、新工具，都会反过来推动下一轮对齐。

## 9.12 后训练阶段也是在更新参数吗

> **我：** 那后续的RLHF和对齐之类的也是更新参数吗？

> *（这一问出现在会话 5 的后半段，紧接在注意力机制与数学抽象的讨论之后。当时的语境是：你刚弄明白「机器只在高维空间里调坐标」，于是顺着问后训练是不是也在做同一件事。所以下面这份回答是从几何/高维空间的角度讲的，和本章前面 9.1–9.11 的流程视角正好互补。）*

**完全正确！RLHF 和对齐（Alignment）阶段，本质上绝对是在更新参数。**

预训练是在做「填鸭式」的知识灌输，而 RLHF 和对齐是在做**「价值观和行为的微调（Steering）」**。它们依然离不开那套数学机制（梯度下降、反向传播、在高维空间里调整几何分布），只是**优化目标（Loss Function）变了**。

### 1. 第一阶段：SFT（有监督微调）—— 模仿人类

- **做法**：给模型喂几万条高质量的「问答对」（比如：问「怎么造炸弹」，答「我不能回答这个问题」）。
- **参数更新**：是的，全量（或部分）参数更新。模型原本只会「接龙」，通过这批数据，参数被强行掰到了「对话助手」的轨迹上。数学上还是交叉熵损失，预测下一个词的分布。

### 2. 第二阶段：训练奖励模型（Reward Model）—— 训练「裁判」

- **做法**：人类给模型的多个回答打分排序（A 回答比 B 好）。用这些数据训练一个**新的模型**。这个模型不生成文本，只输出一个分数。
- **参数更新**：这里更新的是**奖励模型**的参数，而不是大模型本身的参数。
- **目的**：用奖励模型代替人类去自动打分。

### 3. 第三阶段：RLHF / 对齐（PPO 或 DPO）—— 真正的「洗心革面」

这才是核心。这里大模型的参数**被极大地更新了**，但方式不同：

**RLHF（PPO 算法）**

- 大模型（Actor）生成一个回答。
- 奖励模型给它打分（比如 80 分）。
- 这个分数变成「奖励信号（Reward）」，通过**强化学习的梯度算法**反向传播给大模型。
- **参数怎么变？** 如果得了 80 分，模型就强化生成这个回答时的参数权重方向；如果得了 −50 分，就往反方向猛调。
- 同时还有一个「惩罚机制（KL Penalty）」，防止模型为了拿高分把语言逻辑全忘了、胡说八道。

**DPO（直接偏好优化，现在更主流）**

- 直接跳过奖励模型，用人类的偏好数据（A 比 B 好）构造一个特殊的损失函数，一口气更新大模型的参数。
- 数学上更优雅、更稳定。

### 从「数学抽象」角度理解对齐

既然词向量=高维空间里的几何坐标，那么 **RLHF 和对齐，就是在对这个高维空间进行「扭曲」或「平移」**：

- **预训练**：在高维空间里尽可能全面地铺开，把所有人类知识、脏话、逻辑、偏见全塞进这个几何空间。此时坐标分布是「原始人类语料」的形状。
- **对齐**：强行修改这个空间的**地形**——
  - 把「友善、诚实、拒绝违法」的向量区域，通过参数更新拉得更近、更容易被模型踩到；
  - 把「暴力、歧视、幻觉」的向量区域，通过参数更新压扁、推远，甚至加上「负梯度」让它无法生成。
  - 这就是为什么微调之后的模型突然变得「温顺」了——它的高维空间几何结构被重塑了。

### 一个极其关键的工程现实：全量微调 vs 轻量微调（LoRA）

在讨论「更新参数」时要注意，实际工程中对齐不一定更新**全部**参数：

1. **全量微调（Full Fine-tuning）**：把几千亿个参数全部重新算一遍。成本极高（几千张 H100 跑几周），效果最彻底。
2. **LoRA（低秩适配，Low-Rank Adaptation）**：现在开源界的主流。冻结主模型几千亿的参数，只在旁边外挂两个极小的矩阵（比如几百万参数）。
   - 数学上利用矩阵的低秩分解：`原参数 W + 微调量 ΔW = W + B×A`。
   - 对齐时**只更新 B 和 A 这两个小矩阵**，相当于在原模型的高维空间里做了一个极其微小的「局部旋转」。
   - 效果：成本降低约 100 倍，且能保留原模型的知识，只改变行为。

### 总结

- 预训练是**「寒窗苦读，积累知识」**（更新所有参数）。
- RLHF 和对齐是**「步入社会，学习人情世故和道德规范」**（同样更新参数，但目的是重塑向量空间里的概率分布，让输出符合人类价值观）。

整个大模型的训练生命周期，自始至终都在做同一件事：**在高维几何空间里，用微积分这个工具，不断调整坐标和地形，直到它输出的概率分布能完美契合人类的语言和偏好。**
