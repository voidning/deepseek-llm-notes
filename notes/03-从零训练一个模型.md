## 3.1 从 0 造一个 LLM 的完整流程

先说明：如果是 GPT-4 级前沿模型，这不是个人能做的，通常需要**数千到数万张 GPU、数千万到数亿美元、几百人团队、几个月到一年以上**。但流程本身是清楚的。

### 总流程图

```text
目标与预算
  ↓
数据采集 → 清洗/去重/过滤 → Tokenizer → Token化数据集
  ↓
模型架构设计 → 分布式训练代码 → 预训练
  ↓
检查点
  ↓
后训练：SFT → 奖励模型 → RLHF/DPO → 安全对齐
  ↓
评估：基准测试 + 人工评估 + 安全评估
  ↓
量化/推理优化 → 部署 → 监控 → 迭代
```

---

### 1. 定目标和预算

这一步决定后面所有事。要确定：

- 参数量：7B、70B、175B、还是 MoE 总参 1T+？
- 激活参数量：Dense 还是 MoE？
- 上下文长度：4K、32K、128K？
- 多模态：只文本，还是图像/音频/视频？
- 目标：通用助手、代码、数学、医疗、法律？
- 预算多少？多少张 GPU、训练多久？

算力粗略公式：

$$C \approx 6ND$$

- $N$：参数量
- $D$：训练 token 数
- $C$：训练 FLOPs

例子：70B 模型，2T tokens：

$$C \approx 6 \times 70\text{e}9 \times 2\text{e}12 = 8.4\text{e}23 \text{ FLOPs}$$

A100 BF16 实际约 150 TFLOPS，1000 张卡约 65 天。加上调参、失败、后训练，实际更久。

---

### 2. 数据收集与清洗

**这是大模型最核心的部分之一。** 大模型不是先写代码，而是先搞数据。

**数据来源**：网页（Common Crawl）、书籍、论文、百科、代码（GitHub）、数学（arXiv、竞赛题）、对话、论坛、问答、多语言语料。

**清洗**：

- 去重：文档级、段落级、句子级
- 质量过滤：分类器、启发式规则
- 隐私过滤：删个人信息
- 毒性/违法内容过滤
- 去污染：删掉和测试集重叠的内容
- 版权和合规处理
- 配比：代码、数学、多语言、通用文本按比例混合

数据质量往往比数量更重要。垃圾数据喂多了，模型只会更会生成垃圾。

---

### 3. 训练分词器

把文本切成 token。比如英文 `unhappy` 可能变成 `un + happy`，中文"不快乐"可能变成 `不 + 快乐`。

- 常用算法：BPE、Unigram、SentencePiece、WordPiece
- 词表：32K ～ 200K，比如 3 万、5 万、10 万 token
- 产出：把所有文本变成 token ID

词表越大，序列越短，但嵌入矩阵越大。

**数据打包**：Tokenize → Shuffle → 分片存储 → 流式加载，避免一次性读入内存。

---

### 4. 设计模型架构

现代 LLM 基本是 **Decoder-only Transformer**。

关键组件：

- Embedding
- 位置编码：RoPE、ALiBi
- Attention：MHA、GQA、MQA
- MLP：SwiGLU
- Norm：RMSNorm
- 残差连接
- 输出层：投影到词表

要定的超参数：层数、hidden size、attention heads、KV heads、FFN 中间维度、上下文长度、词表大小、激活函数、归一化位置、是否用 MoE。

如果做 MoE：专家数、每 token 激活几个专家、路由网络、负载均衡损失。

**这就是"结构"。结构定了以后，一般训练中不再改。**

---

### 5. 随机初始化参数

所有参数一开始都是随机数：嵌入矩阵、注意力权重、前馈网络权重、输出层。

但也不是随便乱来，初始化方式有讲究（正态分布、均匀分布、Xavier、Kaiming 等），不能太大也不能太小，否则训练会爆炸或学不动。

---

### 6. 预训练：最核心、最烧钱的阶段

这是大模型真正"读书"的阶段，可能占整个训练 **90% 以上**的算力。

目标：**自回归预测下一个 token**。

损失函数：

$$L = -\sum \log P(x_t \mid x_{<t})$$

训练循环伪代码：

```python
for batch in dataloader:
    input_ids, labels = batch

    with autocast(dtype=torch.bfloat16):
        logits = model(input_ids)
        loss = cross_entropy(logits, labels)

    loss.backward()          # 反向传播：算梯度
    clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()         # 优化器：更新参数
    scheduler.step()
    optimizer.zero_grad()
```

**反向传播的位置**：前向传播 → 算 loss → `loss.backward()` → 优化器更新。
它负责算梯度，不决定学什么规律；决定学什么的是数据、架构、目标函数。

预训练可能持续几周到几个月。要监控 loss 曲线、吞吐、硬件利用率。

**关键技术**：

- 框架：PyTorch、Megatron-LM、DeepSpeed、FSDP
- 并行策略：数据并行、张量并行、流水线并行、序列并行、ZeRO/FSDP
- 精度：BF16/FP16，可选 FP8
- 优化器：AdamW、权重衰减、梯度裁剪
- 学习率：Warmup、Cosine decay
- 工程：检查点保存、容错重启、日志监控、吞吐、MFU、loss、梯度范数

---

### 7. 评估和调参

评估必须贯穿始终。

**自动基准**：MMLU、BBH、GSM8K、MATH、HumanEval、MBPP、MT-Bench、AlpacaEval、多语言与安全基准。

**人工评估**：A/B 测试，有用性、真实性、安全性评分。

**还要做**：数据污染检测、偏见评估、越狱测试、长上下文测试。

训练中还要看：验证集 loss、困惑度、下游任务表现、是否过拟合、是否欠训练、不同规模对比。

如果发现不对，可能要：调学习率、调 batch size、换数据配比、重启训练、改并行策略。

**训练不是一次成功，经常要反复试。**

---

### 8. 后训练 / 对齐

预训练完的模型只是"会续写"，还不会好好回答问题。后训练让它变成助手：

- **SFT 指令微调**：数据是"指令-回答"对、多轮对话；目标：学会遵循指令、对话格式；方法：仍然用下一个 token 预测，但**只在回答部分算 loss**。
- **奖励模型**：收集人类偏好数据（A 回答 vs B 回答），训练奖励模型给回答打分。
- **RLHF / DPO**：RLHF 用 PPO/GRPO 优化策略，让模型输出更符合人类偏好；DPO 是直接偏好优化，更简单稳定。目标：有用、诚实、无害。
- **安全对齐**：红队测试、拒绝有害请求、偏见、隐私、法律合规。
- **工具调用**：教它用搜索、代码、API。

后训练阶段也有反向传播，只是损失函数和训练目标不同。这一步算力比预训练小很多，但决定模型好不好用。

---

### 9. 推理与部署

训练完的模型要能服务。

**优化**：量化（INT8、FP8、4bit）、KV Cache、PagedAttention、连续批处理、投机解码。

**推理引擎**：vLLM、TensorRT-LLM、TGI。

**服务**：API、限流、监控、成本控制、延迟优化。

推理时**只做前向传播**，不做反向传播，不更新参数。

---

### 10. 持续迭代

上线不是结束，大模型是循环工程：

```text
数据 → 训练 → 评估 → 发现问题 → 补数据/调架构/改后训练 → 再训练
```

- 收集用户反馈
- 发现 bad case
- 补数据
- 重新微调
- 安全更新
- 发新版本

缩放定律可以帮助：先用小模型试超参，再放大。

### 一句话总结

**从零训练大模型 = 定目标 → 搞数据 → 训分词器 → 定架构 → 随机初始化 → 预训练 → 评估调参 → 后训练对齐 → 部署优化 → 持续迭代。**

预训练是"海量阅读自学"，后训练是"老师教它做人"。
结构是人给的，初始参数是随机的，能力是数据和算力在反向传播中一点点雕刻出来的。

## 3.2 上面那条主线之外，容易漏掉的环节

> **我：** 帮我总结一下上面的知识？让后[然后]帮我补充一下还有那些关键的流程

完整大模型训练不只是"前向、反向、更新"这个循环，还包括下面这些关键环节：

1. **数据准备**
   - 语料收集、清洗、去重、质量过滤、隐私和安全过滤。
   - 训练 tokenizer，比如 BPE、SentencePiece。
   - 把文本转成 token id，拼接、切块、打包成长序列。
   - 构造输入和标签：输入 `tokens[:-1]`，标签 `tokens[1:]`。

2. **模型初始化与结构**
   - 随机初始化 embedding、注意力、FFN、输出层等。
   - 位置编码，比如 RoPE、ALiBi、绝对位置编码。
   - 归一化，比如 LayerNorm、RMSNorm。
   - 激活函数，比如 GeLU、SwiGLU。
   - 残差连接、因果注意力掩码。

3. **预训练循环细节**
   - 学习率调度：warmup、cosine decay、WSD 等。
   - 梯度裁剪，防止梯度爆炸。
   - 权重衰减，通常只对部分参数生效。
   - 混合精度：FP16、BF16、FP8。
   - 梯度累积，解决显存不足。
   - 损失缩放，配合 FP16。

4. **分布式与并行**
   - 数据并行：不同 GPU 处理不同 batch。
   - 张量并行：一层内部拆到多卡。
   - 流水线并行：不同层放到不同卡。
   - 序列并行、专家并行。
   - ZeRO、FSDP 等显存优化。
   - All-Reduce、All-Gather、Reduce-Scatter 等通信。

5. **显存与速度优化**
   - Flash Attention。
   - Activation Checkpointing，用计算换显存。
   - CPU Offload、Paged Optimizer。
   - 算子融合、通信重叠。

6. **稳定性与监控**
   - 监控训练损失、验证损失、梯度范数、学习率、吞吐。
   - 处理 loss spike：回滚 checkpoint、调小学习率、跳过坏数据。
   - 保存和恢复 checkpoint。
   - 记录日志，比如 TensorBoard、WandB。

7. **评估**
   - 验证损失、困惑度 PPL。
   - 下游 benchmark。
   - 生成样例质量。
   - 判断过拟合、数据泄漏、污染。

8. **后训练与对齐**
   - 监督微调 SFT。
   - 奖励模型、RLHF。
   - DPO、IPO 等偏好优化。
   - 安全对齐、工具使用、指令跟随。

9. **推理部署**
   - KV Cache。
   - 量化、蒸馏、剪枝。
   - 批处理、连续批处理。
   - 采样策略：temperature、top-k、top-p。
   - 推理时是自回归逐 token 生成，和训练时并行预测不同。

**一句话主线**：

**数据 → tokenizer → 打包成 batch → 前向预测下一 token → 交叉熵损失 → 反向传播算梯度 → 梯度累积/裁剪 → 优化器 step 更新参数 → 调度器更新学习率 → 周期评估和保存 checkpoint → 后训练对齐 → 推理部署。**

## 3.3 个人想训一个最小的大模型，要付哪些成本

> **我：** 就是我个人想训练一个最小的大模型。我要付出哪些成本。可以零成本训练出来吗？没啥功能都行

想个人训练一个最小的模型，**完全可以做到接近零成本，甚至是真的零成本**。现在的开源项目和免费算力平台，已经把门槛降到了普通爱好者也能玩的程度。你不需要"没啥功能都行"这么悲观，用现成的方案，花几块钱就能训练出一个能进行简单对话的小模型。

### 💰 成本构成

训练一个小模型，主要成本是这几块，但都可以压得很低：

- **算力成本（最大开销）**：这是训练模型最主要的成本。如果不想花钱，可以使用免费云平台；如果图方便，可以租用云 GPU，成本极低。
- **数据成本**：几乎为零。很多开源项目（如 MiniMind）会直接提供预处理好的高质量数据集，你直接下载即可，省去了自己爬取和清洗的麻烦。
- **时间成本**：对于最小的模型，训练时间通常在**几分钟到几小时**之间，非常适合个人尝试。

### 🚀 两条可行路径

#### 路径一：使用免费云算力（真正的零成本）

- **平台选择**：**Google Colab** 免费版提供约 **16GB** 显存的 Tesla T4 GPU；**Kaggle** 则提供 **30 小时/月** 的免费 GPU 使用时长，通常是 Tesla P100 或 T4。
- **可行性**：这些平台的算力足以训练一个参数量在 **3.5M 到 10M** 之间的微型 GPT 模型（例如 nanoGPT 的 tiny 配置），训练可能在 **20 分钟到 3 小时** 内完成。
- **主要限制**：免费资源有每日/每月的使用时长限制（如 Colab 约 12 小时/天），且实例可能会自动断开，需要注意保存检查点（checkpoint）以便断点续训。

#### 路径二：租用低成本 GPU（约 3 元人民币）

如果你希望训练过程更稳定，或者想尝试稍大一点的模型（如 **25.8M** 参数的 MiniMind），可以租用云 GPU。

- **成本**：根据 MiniMind 项目作者的实践，在单张 **NVIDIA 3090** 上，仅需约 **2 小时** 和 **3 元人民币** 的服务器租用成本，就能完成一个基础对话模型的训练。
- **性价比**：这几乎是"奶茶价"，却能让你体验完整的从 0 到 1 的训练流程，性价比极高。

### 🧱 最小模型项目推荐

| 项目 | 参数量 | 特点 | 硬件要求（最低） | 训练时间 |
| :--- | :--- | :--- | :--- | :--- |
| **nanoGPT (Tiny)** | ~3.5M | 极简字符级模型，代码清晰，适合学习原理 | **CPU 即可** | ~20 分钟（CPU） |
| **MiniMind** | **25.8M** | 完整的 LLM 训练流程，具备流畅对话能力 | 消费级 GPU（如 RTX 3090） | ~2 小时 |
| **nanochat (Karpathy)** | 未明确 | Andrej Karpathy 新作，目标是以 **<100 美元**成本训练出 ChatGPT 的小型版本 | 云端 GPU | ~4 小时（100 美元） |

对于入门，**MiniMind** 是一个非常好的起点。它的最小版本仅有 **25.8M 参数**，是 GPT-3 的 1/7000，但已能进行流畅对话，且提供了包括预训练、SFT 微调、LoRA 等在内的**全流程代码**。

### 💻 硬件与数据门槛

- **硬件**：如果你有 **6GB** 显存的 NVIDIA 显卡，就可以开始训练非常小的模型了。显存 **8GB** 以上会更从容。
- **数据**：无需自己准备。MiniMind 等项目都提供了预处理好的数据集，直接下载即可使用，包含预训练和指令微调数据。

### ⏳ 学习曲线才是最大的隐性成本

- **训练时间**：从**几分钟**（nanoGPT CPU 训练）到**几小时**（MiniMind GPU 训练）不等，取决于模型大小和硬件。
- **学习成本**：你需要
  1. 基本的 **Python** 和 **PyTorch** 知识。
  2. 理解 Transformer 的基本概念（不必深入数学）。
  3. 学会使用 Git 和命令行。
  4. 阅读并理解开源项目的 README 文档。

### 💎 总结

- **零成本方案**：利用 **Google Colab / Kaggle** 的免费 GPU，训练 **nanoGPT** 这类微型模型，体验完整流程。
- **低成本方案**：花**几块钱**租用 GPU，基于 **MiniMind** 等优秀项目，训练一个具备基础对话能力的模型。
- **核心成本**：真正需要投入的不是金钱，而是你**学习相关知识的时间**。一旦跑通一次，你对大模型的理解会深刻得多。

## 3.4 5 年程序员 + AI 辅助，够不够

> **我：** 我是一个5年的程序员了。很多东西不懂也没关系，应该可以先学，特别现在有AI的情况下

完全可以。**5 年程序员 + AI 辅助，已经足够你从零跑通一个最小大模型了。** 你缺的不是能力，而是"先动手跑一遍"的经验。数学不用全懂，Transformer 不用手推，甚至代码都不用从零写。现在开源项目和 AI 已经把门槛降到"会 Python、会用命令行、能看懂报错"就能开始。

关键是路线要对：**先跑通，再理解，再改，再训练自己的。**

### 你的优势

5 年程序员意味着：会 Python、Git、命令行、调试；能看懂项目结构、README、配置文件；知道怎么装环境、处理依赖、看日志；遇到报错不会慌，会搜、会问 AI。

这些比"数学好不好"重要得多。训练大模型本质上是一个工程活 + 实验活，不是考试。

### 推荐路线：从零到最小对话模型

**第 1 步：跑通 nanoGPT（1 个周末）**
目标：不写新代码，先让一个微型 GPT 在免费 GPU 上训起来。
平台：Google Colab 或 Kaggle。项目：Andrej Karpathy 的 **nanoGPT**。数据：莎士比亚文本，项目自带。任务：字符级预测下一个字符。

你会看到损失从 4.0 降到 1.5，模型开始生成类似莎士比亚的胡话——这一步让你亲眼看到：**随机参数 → 前向 → 损失 → 反向 → 更新 → 生成文本**。

**第 2 步：改参数，理解训练循环（2–3 天）**
改 `n_layer`、`n_embd`、`n_head`、batch size、学习率、上下文长度，看 loss 怎么变。让 AI 逐行解释 `train.py`、`model.py`。你不需要背公式，但要大概知道：token 怎么变成 embedding；attention 在干嘛；loss 怎么算；反向传播怎么更新参数；为什么学习率太大会炸。

**第 3 步：换成中文数据（3–5 天）**
把莎士比亚换成中文小数据集：中文小说片段、对话数据、你自己的聊天记录（脱敏）。重新训练分词器，或者用现成 tokenizer。你会遇到编码、分词、数据格式问题，这些正是程序员擅长的。

**第 4 步：跑 MiniMind，训练一个能对话的小模型（1–2 周）**

## 3.5 个人还有创新空间吗

> **我：** 但是我们可以有小创新吗？没啥创新的空间吧

不是没空间，而是**"大创新"的空间确实被大厂占了，"小创新"的空间反而很多**。
个人很难发明下一个 Transformer、下一个 Scaling Law、下一个 GPT-4。但"小创新"不需要跟大厂正面拼，它可以是**新组合、新数据、新场景、新评测、新工具、新应用**。

先把创新分两层：

- **大创新**：新架构、新训练范式、新 Scaling Law、新基础模型。需要海量算力、数据、团队。个人基本玩不起。
- **小创新**：在已有模型和开源项目上，针对具体问题做出可复现的改进。个人完全能做，而且大厂往往看不上、做不细。

### 你能做的「小创新」方向

1. **垂直领域小模型**：用法律、医疗、编程、客服、古诗、个人笔记等特定数据，微调一个 25M～1B 的小模型。目标不是通用能力，而是在某个细分任务上超过同尺寸通用模型。比如一个专门给中文古诗续写的小模型，或者一个专门生成 SQL 注释的小模型。
2. **数据创新**：数据配比、清洗规则、合成数据、课程学习、去毒、隐私过滤。大厂做通用数据，你可以做"小而精"的数据集。比如构建一个高质量的中文技术面试问答数据集，用它微调小模型。
3. **训练和推理效率**：小模型在 CPU、树莓派、手机端跑。量化、剪枝、蒸馏、LoRA、稀疏化、KV Cache 优化。比如让 MiniMind 在 4GB 显存甚至手机上流畅对话。
4. **架构微调与消融实验**：不改 Transformer 整体，只改小地方——位置编码、激活函数、归一化位置、注意力变体、层数配置。做对照实验，看哪个配置在中文小模型上更好。这种"小消融"很容易发博客、开源，也有实际价值。
5. **评测创新**：现在小模型缺好的中文评测集。你可以做一个"小模型中文能力榜"，或者某个垂直任务的评测基准。评测本身也是创新，因为大家需要知道小模型到底行不行。
6. **应用层创新**：RAG、Agent、工具调用、记忆系统、多模型路由。比如小模型 + 检索，做一个个人知识库问答助手。大模型做通用，小模型做专用，配合起来效果可能很好。
7. **可解释性和可视化**：小模型更容易分析。做注意力可视化、神经元分析、词向量降维、训练过程动画。这既是创新，也是很好的学习方式。
8. **工具链和教育工作**：一键微调脚本、Colab notebook、自动训练流水线、模型对比工具。让更多人能低门槛训练小模型，这本身就是贡献。

### 关键是怎么做

- 先复现一个 baseline，比如 nanoGPT 或 MiniMind。
- 选一个**具体问题**，比如"中文古诗生成""代码注释生成""客服意图分类"。
- 只改**一个变量**：数据、微调方法、量化、架构细节。
- 做**对照实验**，记录结果。
- 如果比 baseline 好，哪怕好一点点，就是小创新。
- 开源代码、写博客、发视频，积累影响力。

举个例子：你可以在 MiniMind 上，用 5000 首古诗做 LoRA 微调，然后设计一个"古诗续写评测集"，对比微调前后。如果微调后模型在古诗任务上明显更好，同时通用对话没怎么退化，这就是一个完整的小创新。成本可能只要几块钱 GPU 和几天时间。

所以，不是没创新空间，而是**不要用"大厂标准"要求自己**。大厂拼的是通用智能，你拼的是长尾、垂直、效率、应用、评测、工具。这些领域大厂做不过来，个人反而有优势：快、灵活、贴地气。

一句话：**大创新很难，小创新很多。个人训练小模型，目标不是打败 GPT，而是解决一个具体问题，做出可复现的改进。这就够了。**

## 3.6 「那这不就是个专用模型吗」

> **我：** 但这个本质上来说是个专用模型了是吧。只解决一类问题。

对，你判断得基本没错：**个人从零训练或微调出来的小模型，本质上大概率就是专用模型，甚至不是"解决一类问题"，而是"解决一个很窄的任务"。**

但这里要拆成三层看：

### 1. 从「模型本身」看：就是专用

小模型参数量小、数据窄、算力少，容量有限。

- 25M 的 MiniMind，能对话，但知识少、推理弱、泛化窄；
- 你用古诗微调，它就是古诗续写模型；
- 你用客服数据微调，它就是客服意图分类/回复模型；
- 你用代码注释微调，它就是代码注释生成模型。

它的权重里只装了那个领域的东西。你让它去聊医学、写法律合同、做数学证明，大概率不行。所以从模型本身看，**它就是专用模型，只解决一类问题，甚至只解决一个任务。**

### 2. 从「系统」看：可以假装通用

但如果你不是只交出一个模型，而是做一个系统，那就不一定了。比如：

- 小模型做意图识别：判断用户要问什么；
- 路由到不同专用模型或大模型 API；
- 加 RAG 查知识库；
- 加工具调用做计算、搜索、数据库查询；
- 加记忆系统保存上下文；
- 加 Agent 做多步规划。

这时候，用户感觉它什么都能干。但底层不是"一个通用小模型"，而是**多个专用模型 + 工具 + 大模型 + 检索 + 路由**的组合。

所以：**模型本身是专用的，系统层面可以表现出通用性。**

### 3. 通用和专用不是二选一，是光谱

- 大厂的基础模型：通用底座，但部署成助手后，也常被后训练、对齐、工具化，变得"有条件专用"；
- 行业模型：法律、医疗、金融，领域专用；
- 个人小模型：任务专用、领域专用；
- 应用系统：通用体验，专用模块组合。

通用模型像大学，什么都知道一点。专用模型像专科医生，只治一种病，但可能治得更好、更便宜、更快。

### 4. 专用不是低端，反而是落地主流

商业里真正赚钱的，很多是专用：客服意图分类、合同条款抽取、代码补全、医疗问答、法律检索、工业质检、推荐排序。

大厂做通用底座，个人和小团队做专用落地，这是合理分工。你不可能训练出下一个 GPT-4，但你可以做一个**某个细分领域最好用的小模型或系统**。

### 5. 个人路线怎么选

**如果你想"通用"**：别从零训小模型；用开源大模型或 API 做底座；你做 RAG、Agent、工具、路由、记忆、评测；创新在系统层，不在模型权重层。

**如果你想"做模型"**：接受专用；选一个极窄场景；把数据、评测、效率做到极致；小模型也能有商业价值。

**如果你想两者结合**：小模型做路由、分类、嵌入、草稿；大模型做生成、推理、兜底；系统看起来通用，成本还低。

### 一句话总结

**对，个人训练的小模型本质上就是专用模型，只解决一类甚至一个问题。**
但这不丢人，也不代表没创新。**通用是系统能力，不是单模型能力。**
个人最现实的路线是：做专用模型，或者用专用模块 + 大模型 + 工具，组合出一个看起来通用的系统。

## 3.8 「从 0」的另一种理解：不克隆任何现成仓库

> **我：** 我是想从0开始的

明白，你说的"从 0"是：不克隆 nanoGPT、MiniMind；不加载预训练权重；不用 `transformers` 高层封装；自己写模型、自己初始化、自己训练。

这个完全可以。你是 5 年程序员，从 0 手写一个**最小字符级 GPT**，用 PyTorch 的自动求导，是最现实、最不折磨自己的路线。**不要手写反向传播，那是自虐，没必要。**

目标先定小：

> 字符级语言模型，参数量 0.1M～1M，CPU 能跑，Colab 免费 GPU 几分钟到几十分钟能跑出 loss 下降。

### 从 0 的路线

1. **准备纯文本**：任意中文/英文 txt，编码 UTF-8。
2. **建字符表**：所有字符 → 整数 id。
3. **切训练样本**：输入 64 个字符，预测下一个字符。
4. **写模型**：Embedding + 位置编码 + 单头注意力 + MLP + 输出层。
5. **训练循环**：交叉熵 loss → backward → AdamW step。
6. **生成**：给一个开头，反复预测下一个字符。
7. **再加多头、多层、残差、LayerNorm**，逐步逼近 Transformer。

### 最小可跑代码骨架

只用 PyTorch，不依赖 transformers。建一个 `train.py`：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

# ---------- 1. 数据 ----------
text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
data = torch.tensor([stoi[c] for c in text], dtype=torch.long)

vocab_size = len(chars)
block_size = 64      # 上下文长度
batch_size = 32
n_embd = 64          # 向量维度
n_layer = 2

print("词表大小:", vocab_size, "文本长度:", len(data))

def get_batch():
    ix = torch.randint(len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i:i+block_size] for i in ix])
    y = torch.stack([data[i+1:i+block_size+1] for i in ix])
    return x, y

# ---------- 2. 单头自注意力 ----------
class Head(nn.Module):
    def __init__(self):
        super().__init__()
        self.key = nn.Linear(n_embd, n_embd, bias=False)
        self.query = nn.Linear(n_embd, n_embd, bias=False)
        self.value = nn.Linear(n_embd, n_embd, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k = self.key(x)
        q = self.query(x)
        v = self.value(x)

        wei = q @ k.transpose(-2, -1) * C ** -0.5
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        wei = F.softmax(wei, dim=-1)
        return wei @ v

# ---------- 3. Transformer Block ----------
class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = Head()
        self.ln2 = nn.LayerNorm(n_embd)
        self.mlp = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),
            nn.ReLU(),
            nn.Linear(4 * n_embd, n_embd),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        x = x + self.mlp(self.ln2(x))
        return x

# ---------- 4. 最小 GPT ----------
class MiniGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, n_embd)
        self.pos_emb = nn.Embedding(block_size, n_embd)
        self.blocks = nn.Sequential(*[Block() for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        x = self.token_emb(idx)
        x = x + self.pos_emb(torch.arange(T, device=idx.device))
        x = self.blocks(x)
        logits = self.lm_head(self.ln_f(x))

        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits.view(B * T, -1),
                targets.view(B * T)
            )
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens=200):
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -block_size:]
            logits, _ = self(idx_cond)
            logits = logits[:, -1, :]
            probs = F.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
            idx = torch.cat((idx, idx_next), dim=1)
        return idx

# ---------- 5. 训练 ----------
device = "cuda" if torch.cuda.is_available() else "cpu"
model = MiniGPT().to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)

for step in range(5000):
    x, y = get_batch()
    x, y = x.to(device), y.to(device)
    # …（原文在此处截断，后续为标准循环：forward → cross_entropy → backward → step）
```

> 相关章节：训练循环里每一步在做什么，见 **02**；多头注意力、位置编码、残差为什么长这样，见 **06**、**07**。
